# 海信超声主机 补采数据协议 (Hisense acquisition protocol)

用于标定 `image_autotune/hisense_backend_sim.py` 的后端模型，并验证 `image_autotune/hisense_tgc_optimizer.py`
给出的参数建议。

现有的 20260814 三帧数据只够标定 **TGC 一个轴**，且只覆盖滑块 70–185 区间。
本协议补齐其余标定，并给出可复现的验证基线。

---

## 0. 术语：什么是一个「场次」

**一个场次 = 从把探头固定在仿体上、到把探头取下来之间，那一段连续不中断的时间。**
场次内探头一动不动，耦合剂不补涂，探头与预设不更换。

第一阶段的 10 帧应当**全部在同一个场次内完成**。

出现下列任何一种情况，就算进入了新场次，**必须重新采一组 S0**：

- 探头被取下、移动，或支架被碰过
- 重新涂了耦合剂
- 更换探头或预设
- 隔了一顿饭 / 隔天再采

原因见 S0 第 1 条：深度响应曲线 C(z) 与探头位置和耦合状态强绑定，跨场次不可复用。

---

## 0. 前提条件（最重要）

| 项 | 要求 |
|---|---|
| 探头 | **固定在支架上，全程不得移动**。这是最大的误差源 |
| 仿体 | 组织仿体，含无回声囊肿与钢丝点目标；位置固定 |
| 耦合 | 一次涂好耦合剂，中途不要补涂（会改变近场） |
| 预设 | L15-4 / 颈动脉（与现有数据一致），单次序列内不得更换 |
| 前端参数 | 每个序列内 `Algo_FeParam.pdt` 必须保持不变 —— 只动触摸屏上的后端参数 |
| 导出 | 每个设置导出**一整个采集目录**（含 `Algo_BC0.bin` 与两个 `.pdt`） |

> 校验方法：采完后运行 `python image_autotune/hisense_loader.py`，
> 同一序列内所有采集的 geometry / probe / freq 应完全一致。

现有三帧在探头固定条件下，深度带电平的帧间最大离散为 **0.17 dB**。
若补采数据的 S0 离散明显大于此值，说明探头或耦合发生了移动，该批数据不可用于标定。

---

## 0b. 关于「设不准」：不需要设准

海信主机的 TGC 只能拖滑块或点预设曲线，**没有数值输入框**。这不影响本协议，因为：

**标定读的是导出文件里 `BEParam.pdt` 记录的实际值 `BTgc1..8Level`，不是你想设的值。**
你拖到哪儿，文件里就记的是哪儿，拟合用的就是那个真值。
所以下面表格中的 192 / 224 / 255 / 64 / 32 / 0 是**瞄准的大致位置，不是必须命中的数字**。

真正需要保证的只有三条：

| 要求 | 为什么 | 怎么做 |
|---|---|---|
| **平档参考帧的 8 档必须严格相等** | `calibrate_depth_response()` 会拒绝非平档数据 | **点预设曲线按钮**（面板上「用户设置 / 标准设置」里那条竖直线形状），不要手拖 8 个滑块 |
| 各档之间要拉开间距 | 间距决定杠杆臂与线性检验能力 | 相邻两次设置的滑块位置差 ≥ 25 档（目测约为全程的 1/10） |
| 同一设置在场次内要可复现 | S0-a/b/c 三次必须是同一设置 | 用 **「另存为」** 把该设置存成用户预设，之后一键调用 |

> **平档参考帧不必正好落在 127。** 代码已支持任意平档值：
> `calibrate_depth_response()` 会扣掉参考帧自身的那份常数增益，
> `calibrate_tgc_db_per_level()` 会按各组自己的参考电平做归一。
> 已验证：把同一帧的参考电平改标成 100 / 160 / 60 / 200，渲染结果**逐像素完全相同**。

另外两端反而最好设：**拖到顶就是 255，拖到底就是 0**，撞到轨道端点是精确的。

## 1. 采集序列

### S0 — 场次参考帧 + 稳定性基线（必做）

| 变量 | 取值 |
|---|---|
| TGC | **8 档严格相等**（点预设里的竖直线；值本身不必是 127）|
| 其余参数 | 用你打算优化的那套预设，固定不动 |
| 帧数 | **3 帧，分散在场次的开头 / 中间 / 结尾** |

> **不要连续拍 5 帧。** 连续帧只能测到秒级的随机噪声，而那个噪声（σ = 0.037 dB）
> 已经比 TGC 拟合残差 0.263 dB 低 7 倍、比死区 0.2 dB 低 5 倍 —— 平均更多帧毫无收益。
> 真正的风险是整场采集期间的**漂移**（探头滑动、耦合剂干涸、支架被碰），
> 那是突变而非高斯噪声，只有把参考帧**拉开时间间隔**才测得出来。
> 现有三帧只跨越 13 秒，因此那个 0.17 dB 的重复性数字对一场 20 分钟采集没有约束力。

**用途有三个，第一个是硬性依赖**：

1. **提供深度响应 C(z) 的参考帧**。`calibrate_depth_response()` 硬性要求一帧平档 TGC 数据，
   而 C(z) 与探头位置、耦合状态强绑定 —— **换一个采集场次，旧的 C(z) 就失效了**。
   因此每个场次都必须自带 S0，不能复用 20260814 的参考帧。
2. 确认探头与耦合在整个场次内确实稳定。
3. 给上机验证步骤一个基线：改善多大才算真改善。

**验收：首帧与末帧的 BC0 深度带电平之差应 < 0.3 dB。**
若超出，说明场次内发生了漂移，该批数据不能用于标定 —— 重新固定探头再来一遍。

> 更正：早先版本说 S0 的用途是标定控制器死区 `DEFAULT_DEADBAND_DB`。
> 在当前「离线仿真 + 参数建议」架构下这是不准确的 —— 迭代是在一帧固定的 BC0 上跑的，
> 帧间噪声根本不进入回路，死区只是仿真的收敛容差。
> 死区标定要等到真正做机器在环闭环时才成为必需。

### S1 — TGC 全量程补齐（第一阶段唯一需要的扩展）

现有数据只覆盖滑块 **70–185**。要放开到 0–255，需要在两端各补几个点。
用**全 8 档统一值**而不是斜坡，好处是同一个滑块值在 8 个深度上都被观测到，
从而把「滑块值」与「深度」两个因素彻底解耦。

用已标定模型预演过全量程后，**两端的可测性完全不对称**，因此必须拆成两个子序列。

#### S1-H 高端（Gain 保持与 S0 相同）

| 序号 | TGC 8 档大致拖到 | 容差 |
|---|---|---|
| S1-H-1 | ~192（约 3/4 高度）| 落在 180–205 都行 |
| S1-H-2 | ~224（约 7/8 高度）| 落在 212–238 都行 |
| S1-H-3 | **拖到顶**（255）| 撞轨道端点，精确 |

预演结果：这三档**全部 8 个深度带都落在可测窗口内，无一饱和**。
原因是本预设下图像整体偏暗（中段峰值仅 46/255），加 8 dB 也远未到顶。
参考帧直接用 S0。

#### S1-L 低端（必须先把图像整体提亮）

| 序号 | TGC 8 档大致拖到 | 容差 |
|---|---|---|
| S1-L-0 | **平档参考帧**（点预设竖直线，与 S0 同一个预设）| 8 档必须相等 |
| S1-L-1 | ~64（约 1/4 高度）| 落在 50–78 都行 |
| S1-L-2 | ~32（约 1/8 高度）| 落在 20–45 都行 |
| S1-L-3 | **拖到底**（0）| 撞轨道端点，精确 |

低端在当前 Gain 下几乎测不到：全 0 档时 8 个带**没有一个**可用，全 32 档也只剩 1 个 ——
图像本来就暗，再减 6–8 dB 就整体压黑了。

**做法**：把 Gain 调高，直到屏幕上中段组织明显变亮（大致到中灰，约 100–150 灰阶），
然后在该 Gain 下先拍一帧 TGC 全 127 作为本子序列的参考帧，再拍 64 / 32 / 0。
预演显示提亮约 12 dB 后，低端各档均可恢复到 8/8 带可测。

> **Gain 具体调多少不重要，也不需要事先知道 Gain 每档是多少 dB。**
> TGC 标定用的是同一子序列内相对于该组平档参考帧的 Δgray，
> 全局 Gain 偏移在相减时**精确抵消**（已验证：Gain 取 0/+12/+24 dB 时，
> 滑块 160 相对 127 的 Δgray 恒为 8.0 灰阶）。
> 唯一的要求是：**子序列内 Gain 不得改变，且该 Gain 下必须有自己的平档参考帧。**

第一阶段合计 **10 帧**：S0 三帧 + S1-H 三帧 + S1-L 四帧。

#### 各序列帧数的依据

| 序列 | 帧数 | 依据 |
|---|---|---|
| S0 | 3 | 1 帧就够做参考（噪声已远低于误差预算）；多出的 2 帧唯一作用是**跨时间检测漂移**，所以要拉开间隔而非连拍 |
| S1-H | 3 | **检验线性所需的最少档数**：1 档测不出弯曲，2 档分不清弯曲与噪声，3 档才能拟二次项并检验其显著性 |
| S1-L | 3 + 1 | 3 档同上；多的 1 帧是该 Gain 下**专属的平档参考帧**，属结构性必需，不是统计需要 |

> 注意补采**不是为了提高斜率精度**。斜率端点误差：现有数据 0.113 dB，
> 两端各补 1 档降到 0.057 dB，各补 3 档降到 0.045 dB —— 全都已远低于 0.263 dB 的拟合残差。
> 补采的真正目的是**验证 dB 域线性假设在端点是否仍成立**（怀疑那里有压缩），
> 这正是 `CALIBRATED_LEVEL_RANGE` 目前被限制在 70–185 的原因。

### 采集顺序（照这个表从上往下做）

S0 的三帧不要连拍，要按下表**卡在时间轴的首、中、尾**，把 S1 的采集夹在中间。

| 步 | 采集 | Gain | TGC 8 档 | 说明 |
|---|---|---|---|---|
| 1 | — | — | — | 固定探头、涂耦合剂，静置到图像稳定 |
| 2 | **S0-a** | 基准（如 75） | 平档预设 | **场次开头**。C(z) 参考帧就用它 |
| 3 | S1-H-1 | 基准 | ~192 | |
| 4 | S1-H-2 | 基准 | ~224 | |
| 5 | S1-H-3 | 基准 | 拖到顶 | |
| 6 | **S0-b** | 基准 | 平档预设 | **场次中间**。与 S0-a 比对，检查 S1-H 期间有无漂移 |
| 7 | — | 调高 | — | 调亮到中段约 100–150 灰阶；**记下 Gain 读数** |
| 8 | S1-L-0 | 高 | 平档预设 | 本组专属参考帧 |
| 9 | S1-L-1 | 高 | ~64 | |
| 10 | S1-L-2 | 高 | ~32 | |
| 11 | S1-L-3 | 高 | 拖到底 | |
| 12 | — | **调回基准** | — | Gain 拨回第 2 步那个读数（屏幕左上角 `G xx`）|
| 13 | **S0-c** | 基准 | 平档预设 | **场次结尾**。与 S0-a 比对，这是整场漂移的判据 |

三帧 S0 的作用各不相同：

- **S0-a**：C(z) 参考帧，以及漂移比对的基准
- **S0-a ↔ S0-b**：夹住 S1-H，定位漂移是否发生在这一段
- **S0-a ↔ S0-c**：夹住整个场次，这是**验收判据（差值 < 0.3 dB）**；
  同时顺带验证 Gain 旋钮拨回原值后能否复现，若 S0-c 与 S0-a 差很多而 S0-b 正常，
  多半是第 12 步 Gain 没拨准而不是探头漂移

### S2 — Gain 轴（阶段二）

| 变量 | 取值 |
|---|---|
| `BUIGainLevel`（Gain 旋钮） | 全程 8 点均布，例如 45/55/65/75/85/95/105/115 |
| TGC | 固定全 127 |

**用途**：标定 `BUIGainLevel` → dB。
目前 `render()` 只接受绝对 `gain_db`，因为这条映射**尚未标定**。

### S3 — 动态范围轴（阶段二）

| 变量 | 取值 |
|---|---|
| 动态范围 | 40 / 50 / 60 / 67 / 80 / 90 |
| 其余 | 固定 |

**用途**：验证 `UIDynamicRangeLevel` 是否就是字面 dB。
当前模型假设它是（DR 67 → 67 dB），S3 可证实或修正。

### S4 — 斑点抑制 / Hipure（阶段二）

| 变量 | 取值 |
|---|---|
| 斑点抑制 | 0 / 1 / 2 / 3 |
| Hipure | 0 / 1 / 2 / 3 |

**用途**：这两个是离散低基数参数，无法解析求逆，需要联合搜索。
S4 提供搜索所需的响应面，并可检验 speckle SNR 指标的敏感度。

## 2. 采完之后

**目录建议**：S0 与 S1-H 同一个 Gain，放在一个目录；S1-L 因为 Gain 不同，单独放一个目录。

```bash
python image_autotune/hisense_analyze.py --data-dir data/hisense_medical
```

重新拟合全部常数并生成图与 `summary.md`。重点看：

1. **TGC 拟合 RMS 残差**应仍在 0.3 dB 量级；
2. **留出验证**（held out）各帧平均误差应 < 1 dB；
3. `intercept at 127` 应接近 0 dB —— 表示扫描点能线性外推回锚点处的零增益，
   是**线性度与自洽性检查**，并非「127 是中性点」的独立证明。

`calibrate_tgc_db_per_level()` 会**自动按 (Gain, 动态范围) 分组**，每组用组内自己的
平档帧作参考，因此可以把两个目录的采集一起传进去做一次合并拟合：

```python
from hisense_backend_sim import calibrate_tgc_db_per_level
from hisense_loader import find_captures, load_capture
caps = [load_capture(p) for p in find_captures("data/hisense_s0_s1h")]
caps += [load_capture(p) for p in find_captures("data/hisense_s1l")]
print(calibrate_tgc_db_per_level(caps, level_range=(0, 255)))
```

> **已知限制**：`hisense_analyze.py` 的深度响应参考帧与留出验证只支持**单一 Gain 组**
> （`flat_tgc_capture()` 取第一帧平档数据）。所以 analyze 请指向 S0+S1-H 那个目录；
> S1-L 是标定输入，不是验证对象，不要期望它在 analyze 里的误差数字有意义。

确认后把 `hisense_backend_sim.py` 中的
`DEFAULT_DB_PER_LEVEL` / `DEFAULT_COUNTS_PER_DB` / `DEFAULT_REFERENCE_DB` 更新为新的拟合值，
并把 `CALIBRATED_LEVEL_RANGE` 放宽到 `(0, 255)`（前提是低端确实拟合出来了）。
之后优化器就不会再报 `hit the slider bound`。

## 3. 上机验证建议参数（闭环的最后一环）

```bash
python image_autotune/hisense_tgc_optimizer.py --capture <采集目录>
```

1. 按输出的 8 个滑块值在面板上设好 TGC；
2. 导出一帧；
3. 对这一帧再跑一次 `hisense_analyze.py`，确认 `uniformity_db` 确实下降；
4. 与机器自带 **Auto** 键（`BAutoOptimizeGain` / `BAutoOptimizeDy`，5 个离散档，只动 Gain 与
   动态范围）的结果对比。

> 注意：优化器把深度均匀性作为目标，而 band 0（近场 0–5 mm）在本仿体上大部分是
> 无回声的耦合层，把它「拉平」到组织电平并无物理意义，只会放大噪声。
> 真人扫查时该带内是皮下组织，问题不存在；用仿体验证时可用 `--target-db` 或
> 忽略 band 0 的建议值。
