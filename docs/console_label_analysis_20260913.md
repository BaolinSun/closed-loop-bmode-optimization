# 海信主机 labels_console.jsonl 分析

日期：2026-09-13。对象：`data/labels_console.jsonl`，对应 `data/hisense_medical`。本次未修改标签或生成算法；新增独立审计脚本、审计结果及本文。分析依据为当前文件与生成实现，而不是 9 月 7 日的旧数据快照。

## 1. 结论

当前文件是“逐帧、部分参数可确定、带不确定性信息的规则/优化器弱监督标签”。数据关联与算术一致性良好，但不能直接当作 422 组可靠、完整、联合最优的六参数真值。

可以用于带掩码的多任务学习和体模控制基线。训练前优先处理：DR 占位标签、尚未划分的 split、后端掩膜计算域不一致、基波死区使用错误 TGC 系数，以及候选步数与机器真实档数不同。Depth 的部分建议是推断而非实测最优；前端三个方向是逐轴条件建议，不能直接假设同时执行仍成立。

## 3. 字段应怎样解释

| 字段组 | 例子 | 含义 |
|---|---|---|
| 身份 | source、frame_id、group_id、family_id | 数据源、采集目录、场次/模式标定组、场景族 |
| 当前前端 | depth_mm、frequency_mhz、focus_mm、imaging_mode | 实际采集时设置；frequency 是发射频率 |
| 当前后端 | gain_db、tgc_levels、dr_ui | 采集时数字后端设置 |
| 建议后端 | optimal_gain_db、optimal_tgc_levels、optimal_dr_ui | 教师求解器给出的设置；DR 当前只是原值 |
| 方向与量 | *_direction、delta_* | 当前设置相对建议的状态，以及建议减当前的差 |
| 可用性 | *_determined、*_at_edge | 是否生成该轴建议，是否受到候选边界/下界限制 |
| 解释证据 | *_basis、*_ladder | 建议的判据说明、采用的候选序列 |
| 后端不确定性 | objective、tolerance、label_uncertainty、deadband_gain_levels、equivalent_count | 教师代价与等效区间，不是客观图像质量评分 |
| 场景/标定风险 | calibration_borrowed、family_unbracketed、family_anchor_starved、notes | 底噪借用、锚点未夹住、锚点不足等 |

`optimal_*` 表示当前教师判据下的建议，不是专家标注真值，也不保证是六参数全局最优。

### 方向不是执行动作名称

所有 delta 采用“建议值减当前值”。direction 描述当前设置的不足或过量：

| 标签 | 当前状态 | 执行方向 |
|---|---|---|
| gain=dark | 相对目标偏暗 | 增加 Gain |
| gain=bright | 相对目标偏亮 | 减少 Gain |
| frequency=low | 当前频率偏低 | 提高频率 |
| depth/focus=shallow | 当前深度/焦点偏浅 | 调深 |
| TGC near/mid/far=low | 对应区域补偿偏低 | 提高该组 TGC |

例如 `frequency_direction=low` 不能翻译成“降低频率”。

`correct` 也不意味着所有数值差严格为零。当前 135 条 Gain=correct 的 delta 均非零，但位于代码计算的死区内。训练方向分类时可以视为无需动作；训练精确修正量时必须明确是否保留死区内的小数修正，避免分类头说保持、回归头持续微调。

八滑块按 near=[1,2,3]、mid=[4,5]、far=[6,7,8] 分组。方向来自组内 delta 平均值；一组中的正负修正可能抵消。因此三组方向适合粗粒度诊断，实际控制仍应看八维 delta。

首条示例：`20260814101607861` 当前 TGC 全 127，建议 `[115,188,131,98,67,96,157,196]`；Gain 建议约 +0.168 dB、+0.821 档，但低于约 3.169 档死区，故 gain_direction=correct。它没有前端比较标签，DR 也未确定。此例不能解释成“六参数均处于最优”。

## 5. 标签是怎样生成的

### 5.1 Gain、TGC：优化器教师

`tools_generate_labels.label_console()` 将 BC0 转成场次标定的 dB，加入 C(z)，构造组织掩膜；在当前 DR 固定的前提下，求平滑的 TGC 形状，并搜索 Gain 与有限 TGC 形状强度候选。

因此后端建议是“当前 DR、当前场次亮度目标、当前掩膜和模拟器下的近优动作”。不是全部八维 TGC 连续空间的无条件全局最优。

亮度目标来自该组被视为常用/接受的设置的组织亮度估计，并非外部专家最优图。因此这些标签包含“保留某类常用亮度”的先验，算法并没有从无标签数据中唯一推导出理想亮度。

模式系数已相对于旧版更新，读取文件中的系数最稳妥：

| 模式 | Gain dB/档 | TGC dB/档 |
|---|---:|---:|
| harmonic | 0.20514 | 0.07810 |
| fundamental | 0.28778 | 0.08226 |

本次核对 current 与 delta 使用这些数值时一致；不能继续套用旧版 0.1705 或 0.06559。

### 5.2 DR：主动保留未知

求解器不搜索 DR，输出 `optimal_dr_ui=dr_ui`、`delta_dr_ui=0`、`dr_direction=correct`、`dr_determined=false`。因此这些行没有提供“最佳 DR”证据。

训练时 DR 损失必须屏蔽。未来可以用目标可见性、裁剪、观察者任务或偏好数据定义 DR 标签，不必要求有逐像素理想图；但不能把当前占位值直接视为监督。

### 5.3 Frequency：覆盖约束下的最高已扫频率

在其余前端设置不变的比较集中，先筛选穿透覆盖当前显示深度（允许 1 mm 容差）的频率，再取最高档；若都不能覆盖，代码直接取最低已扫频率。

这是“覆盖优先、高频优先”的工程规则，不是逐候选直接比较点靶 FWHM 后得到的最优。最高频率分辨率最佳、最低频率穿透最深均是需要在任务数据上验证的前提；无候选覆盖时也应给出覆盖失败状态，不能因 `frequency_determined=true` 就认为已解决任务。

### 5.4 Focus：逐带最小散斑宽度的胜出焦点中位数

每个深度带只比较能够测量的焦点档，选侧向散斑宽度最小者，再取各带胜出焦点的下中位数。它代表对均匀体模可用深度范围的折中聚焦，不是指定囊肿/点靶 ROI 的最优焦点。

阈值会决定哪些焦点与深度带进入比较；“只比较量得到的档位”仍可能产生选择偏差。`focus_determined` 只表示满足生成规则，没有给出候选分差、重复采集方差或最优显著性。

### 5.5 Depth：由穿透与 5 mm 余量推断的取景设置

深度生成器从未被显示视野截断的穿透读数中取最大值，以穿透+5 mm 为目标，通过 framing_cost 选择深度。选用的阶梯来自整个数据目录里出现过的档位，不能自动当作厂家完整硬件阶梯。

264 条 Depth 中，**130 条（49.2%）建议的深度没有出现在其同条件比较集内**。这是生成器允许的取景推断，不是算术 bug，但不等同于在推荐 Depth 下已经测过主机图像。

建议增加 `label_kind=measured_comparison/inferred_framing` 和 `candidate_observed`。离线实采回放不能为这些推断状态伪造观测。

此外 21 条 depth_at_edge=true，可能表示穿透只测到了下界或目标落在已知阶梯外。它们不宜作为精确最优深度回归的高置信度标签。

## 6. 本次发现的实现问题与实际影响

### 6.1 Frequency steps 并非硬件档数：10 条

`frontend_labels()` 对 Frequency/Focus 用比较集自己的 ladder 求索引差。某些频率只扫了 `[4.4,5.0,5.7]`，而已采数据中谐波完整序列为 `[4.4,4.7,5.0,5.3,5.7]`。

例如 `20260901210517471`：当前 5.0 MHz，建议 5.7 MHz，字段写 +1 step；实际需跨过 5.3 MHz，是 +2 个频率档。10 条存在这种差异。其 MHz 差值、方向本身正确。

建议保留 `delta_candidate_steps`，另存由设备档位映射计算的 `delta_hardware_steps`。若执行器支持直接设值，优先下发 optimal_frequency_mhz 并核对设置回读。

### 6.2 组织掩膜图像与噪声阈值不在同一处理阶段

在 `label_console()` 中：

```text
db = raw_bc0_db + C(z)
valid_mask = db > raw_noise_floor + margin
```

噪声底在原始 BC0 dB 上测量，图像却已经加了 C(z)。若要判断原始组织高于原始噪声，应在 raw_bc0_db 上判定；若在修正图上判定，就必须同时将噪声底变成 raw_noise_floor+C(z)。

本次重算全部 422 帧的两种掩膜，差异像素占全图的中位数为 **6.08%**，P90 **15.87%**，最大 **34.61%**。这不是标签出错比例，而是优化评分区域变化的比例。

此问题可能改变 TGC 拟合、曝光评分和 Gain 最优值。本次没有重跑优化生成新标签，因此尚不能量化最优参数改变多少。修正前不宜把教师解视为已验证的最优。

### 6.3 基波死区计算漏传模式 TGC 系数

`labels.label_frame()` 在重建 GainSweep 以估计死区时，没有传入 `db_per_level`，默认使用谐波 0.07810；基波正确模式值应为 0.08226。主求解器已传模式系数，问题主要落在死区估计路径。

本次固定已存最优值、tolerance、原有掩膜与亮度目标，仅将死区计算中的 TGC 系数换成基波值：

- 基波 153 条原死区均能复现，说明诊断与当前标签版本匹配。
- 61 条死区数值改变。
- Gain 方向、near/mid/far 方向均未发生分类翻转。

因此它是需要修正的数值一致性问题，但本次证据不支持宣称已导致方向标签错误。

同类检查还应覆盖 `console_targets()` 的渲染路径：它也未显式传模式 TGC 系数；是否影响目标亮度取决于选中参考帧的 TGC 是否平档。该影响本次未单独量化。

### 6.4 现有验证脚本的相关系数没有处理并列秩

`tests/verify_console_labels.py` 用两次 argsort 代替 Spearman 排名；深度/频率/焦点都是离散档位，重复值很多，应使用平均秩。

本次对相同比较集使用 SciPy 的并列秩处理重新计算：

| 关系 | GEN | THI |
|---|---:|---:|
| 最优频率 vs 显示深度 | -0.889 | -0.770 |
| 最优焦点 vs 显示深度 | +0.816 | +0.731 |

趋势仍与原报告相同，但不能继续引用原脚本的精确相关值。这些关系部分由生成规则决定，也不能当作独立质量验证。

## 7. 不确定性与训练风险

| 项目 | 数量或分布 | 正确解读 |
|---|---|---|
| calibration_borrowed | 154/422 | 当前实现实际表示底噪借用，不是所有标定信息都借用 |
| uncertainty 借用 | 349/422，记录在 notes | 不能只看 calibration_borrowed 来筛选所有借用情况 |
| family_unbracketed | 30 | 该帧没有被本族锚点前后夹住 |
| family_anchor_starved | 17，包含在上述 30 条内 | 场景不变假设缺少足够重复锚点 |
| optimal TGC 有 0 或 255 | 203/422（48.1%） | 处在执行器边界，需报告剩余补偿误差与可信标定范围 |
| 第 8 个最优滑块=255 | 119 | 远场补偿倾向明显，需检查组织/噪声掩膜与任务目标 |
| at_gain_edge | 0 | 仅表示未触发搜索网格边界标志，不代表动作均在实测标定范围内 |
| Gain delta P10–P90 | -2.80 至 +3.71 dB | 主要样本较温和，但尾部仍大 |
| Gain delta 极值 | -20.04 至 +12.51 dB | 执行时需要步长限制和验证；不能从 UI 合法推出物理模型可信 |
| deadband_gain_levels 中位数 | 3.13 档 | correct 是允许的小误差区域 |
| equivalent_count 中位数/最大值 | 7 / 98 | 常有多种近等效候选，不应只以唯一参数回归误差评价 |

`label_uncertainty` 是后端目标函数残差的尺度，不是每条前端 Depth/Frequency/Focus 建议的误差条。它与 tolerance 的单位是目标函数单位；deadband_gain_levels 的单位才是档数。

203 条 TGC 到边界不自动表示错误，也可能是真正的有界最优。但文件没有 tgc_at_edge、边界维数、拟合剩余误差或校准外推标志，训练消费者难以区分“已经补平”与“补偿能力不足”。

## 8. 建议怎样用于训练和控制

1. **按轴掩码训练。** Depth/Frequency/Focus 使用对应 determined；DR 目前全部屏蔽。不能把 null 转成 correct 或 0 mm。
2. **先修后端掩膜与模式系数，再重新生成版本化标签。** 保存旧标签作对照，不覆盖原始数据。改完应比较动作变化、分类变化、是否出现新的边界解。
3. **区分测量、推断和无法确定。** 尤其 130 条 Depth 推断与 21 条边界深度，不应和直接实测候选最优使用相同置信度。
4. **前端条件标签用于单轴策略或候选建议。** 改 Depth 后，原 Frequency/Focus 的条件已变化；执行后应重采、重评，不应把六个 optimal 值拼成一次联合动作真值。
5. **逐轴、按比较集均衡采样。** 避免某个重复采集多的比较集主导损失；报告各模式与各类指标。
6. **按场次/可信场景族划分。** split 当前全空。相同探头位置的重复帧、不同设置与合成扰动必须在同一集合。前端比较依赖整组数据，必须整个比较集一起划分。
7. **说明在线校准的假设。** 当前亮度目标和组标定可能利用整个场次；若测试场次拟合这些量，须将其定义为允许的部署校准流程，不能作为无校准零样本泛化。
8. **评分不只看与伪标签一致。** 增加保留目标的可见性、分辨率、稳定性、实际主机执行后改进及采集预算。跟随规则教师与真实图像变好是两项不同验证。

若初期保守排除对应轴边界、未夹住锚点和锚点不足的行，前端可用行数为 Depth 231、Frequency 224、Focus 151。这只是场景/边界筛选示例，不是经完整可信度评估后的最终训练数量，仍包含部分 Depth 推断。

标签版本建议新增：schema_version、generator_commit、calibration_hash、capture_relpath、comparison_set_id、candidate_frame_ids、label_kind、candidate_observed、delta_hardware_steps、各轴置信度、各标定来源标志、TGC 边界与剩余误差、明确 split。可将无法确定的 DR 方向改成 null，减少误用。
