# 可穿戴超声采集：除 B-mode 图像外还要保存什么

日期：2026-11-03。给自研可穿戴设备的采集数据清单，目标是采到的数据能直接进现有的六参数（深度、频率、聚焦、增益、TGC、动态范围）训练流水线。

---

## 一、先改一件事：B-mode 显示图不是要存的主体

增益、TGC、动态范围是网络要调的三个参数。训练时会给同一帧随机换一组起点设置重新渲染，再问网络该怎么调。显示图已经被当前设置烘死了，做不到这件事。

**要存的是对数压缩之后、用户增益之前的那一级包络阵列**（深度点 × 扫描线）。海信的 `Algo_BC0.bin` 就在这个位置。

保存点**之后**（不能已经作用在数据上）：

- 用户增益、用户可调的 TGC
- 动态范围 / 显示窗宽
- 伽马、对比度等显示映射

保存点**之前**可以有，但要把曲线一起存下来：固定模拟 TGC、空间复合、帧间平均、斑点抑制、对数压缩本身。

显示图还是建议存一份（8 位，裁掉界面只留图像区），但它的作用是校验和给医生阅片用，不是网络输入。

---

## 二、每帧跟着包络一起存

| 字段 | 说明 |
|---|---|
| `frame_id` | 毫秒时间戳，全局唯一，字典序 = 时间序 |
| `min_depth_mm` / `max_depth_mm` | 第一个和最后一个深度点的物理深度 |
| `num_points` / `num_lines` / `width_mm` | 深度点数、线数、总扫描宽度 |
| `imaging_mode` | 基波 / 谐波 |
| `depth_mm` / `frequency_mhz` / `focus_mm` | 前端三参数的**当前值**（谐波下频率按屏显约定写接收频率） |
| `gain_db` | 当前增益，换算成 dB |
| `tgc_levels` | 8 个 TGC 滑块的当前档位 |
| `dr_ui` / `dr_window_db` | 动态范围的界面数值，和它对应的显示窗宽 dB |
| `depth_response_db` | 保存点之前那些深度相关处理的净 dB 曲线；没有就写 `null` |
| `family_id` | 这一帧属于哪一组扫描，见第四节 |

两条容易踩的约束：

- **`num_points` 全数据集恒定**，不要随显示深度变。海信不论显示深度怎么选，包络恒为 870 点，改的是采样起止对应的物理深度。缓存脚本遇到不一致会直接报错退出。
- **`num_lines` 取 128 的整数倍**。横向要池化到 128 线，必须能整除。贴片线数如果到不了 128，告诉我，池化这一步要改。

`gain_db` 和 `dr_window_db` 请让设备算好再存，不要只存档位和界面数字。海信那边这两个换算是扫出来的（界面上的动态范围数字**不是 dB**，实测窗宽 = 0.3519 × 界面值 + 35.09），拟合值带误差，而你们固件里是确定的。

## 三、每场次存一次

| 字段 | 说明 |
|---|---|
| **空采帧** | 一帧**不发射**（或探头悬空、无耦合）的采集，其余设置照常 |
| `counts_per_db` | 包络计数到 dB 的换算系数 |
| `reference_db` | 落在中灰（43/255）的那个显示 dB 值 |
| `subject_id` | 受试者标识 |
| `probe_id` / `preset` / `anatomy` | 探头序列号、预设、部位 |
| 三条档位阶梯 | 设备能选的显示深度、发射频率、发射聚焦，升序列出 |
| `graymap_lut` | dB→灰阶若不是直线，给 256 项查找表；是直线写 `null` |

这里有四项是你们能做而海信做不到的，每一项都替掉一堆拟合：

**空采帧**最值得做。现在底噪只能从显示深度远超穿透极限的帧的深部行估，而大部分数据的深度恰好让它高估 4.7 dB（25.1 mm 处高 11.6 dB），没有深帧的场次只能跨场次借，借来的误差约 2.6 dB。空采帧直接就是接收机底噪，而且给出的是**逐深度曲线**，比「常数 + 拟合的深度响应」更准。每场次每成像模式一帧。

**`counts_per_db`** 必须是整机常数，全部设备全部场次一致。海信不公布它，只能从截图反推，而它和 `reference_db` 强负相关——同一场次不同帧能拟合出 713 / 795 / 827 / 1046 counts/dB，配对的参考值反方向动同样幅度。结果是 dB 刻度逐场次不同、跨场次不可比，这是训练代码里 `--scalar-norm` 三种模式存在的唯一原因。0 dB 取什么物理参考点都行，只要全局一致。

**`depth_response_db`**（第二节）同理。海信包络上游有依赖深度的处理，参数文件里看不到，只能拟合一条残差曲线补上。你们直接从固件给出就不用拟合。

**三条档位阶梯是必需的，不是可选的。** 前端三个输出头在离散档位上做分类/有序回归，档位表就是输出维度；聚焦头用的有序回归还要求档位按物理量升序。

省掉这几项拟合不只是省代码。那套标定现在的残差是逐像素 3–8 灰阶，操作者看过重建图直接评价「明显更差」，而这些误差会进到教师求解器的目标函数里污染标签。

## 四、采集要成组扫描

后端三个参数的最优值能从单帧算出来：包络对增益、TGC、动态范围不变，一帧就能在连续空间里搜最优。

前端三个参数改变包络本身——8 MHz 的采集里没有任何信息能算出 5 MHz 长什么样。所以前端最优只能靠比较**同一探头位置下真实采到的多帧**。每个切面要这样采：

```
参考帧（调好的设置）
  → 沿深度阶梯逐档采，其余设置不动 → 回参考设置
  → 沿频率阶梯逐档采，其余设置不动 → 回参考设置
  → 沿聚焦阶梯逐档采，其余设置不动 → 回参考设置
```

**一次只动一根轴，其余全部不动**，每组扫描之后回到参考设置。设备知道自己在执行哪一段，所以请直接写 `family_id`，不要让我们事后按时间间隔或图像相关去猜——海信人体数据上 15% 的相邻参考帧相关低于 0.75，切族很不可靠，而贴片不动本来就没有这个问题。

另外建议约 10% 的场次加一组后端阶梯：参考设置下「改一项（增益或某个 TGC 滑块）、存一帧、拨回、存一帧」，用来验证闭环的单步行为。

## 五、拿到第一批数据先验三件事

1. 改了增益/TGC/动态范围的两帧，换算出来的 dB 图应当几乎一样（中位差 < 0.5 dB）。**不过关说明保存点取在了后端之后，整套方案在这批数据上不成立。**
2. 用 `gray = clip(round(43 + (dB + TGC曲线 + 增益 − reference_db) / 窗宽 × 255), 0, 255)` 从包络重建灰阶，和设备实际显示的图比，逐像素中位差应当 < 3 灰阶。对不上说明上面某个常数错了，这是最灵敏的自检。
3. dB 的 1% / 50% / 99% 分位跨场次应当稳定。不稳定说明刻度仍然是逐场次的，`counts_per_db` 这一项没落实。

## 六、要你们确认的

1. 处理链里「对数压缩之后、用户增益之前」是哪一级？能在那里取数据吗？
2. `counts_per_db` 能作为固件常数给出吗？不同增益档会改变它吗？
3. `num_points` 能做到不随显示深度变化吗？
4. TGC 是 8 段吗？段中心位置和插值方式是什么？
5. 空采帧能作为一个采集动作暴露给上位机吗？
6. 三条档位阶梯的实际取值（按成像模式分别给）。
7. 贴片的实际线数。
8. 发射是单焦点还是多焦点？多焦点会改变「聚焦该往哪调」这个标签的含义，要重新定义。
9. 有谐波吗？只有基波的话频率阶梯和穿透极限都要重测。

前两项是关键路径。拿到答复我写转换脚本 `tools_build_wearable_training_cache.py`，把你们的数据转成训练缓存。
